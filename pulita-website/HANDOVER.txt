PULITA NEW ENERGY WEBSITE - HANDOVER & HOSTING NOTES
====================================================
For Pulita's IT person. Updated 16 Nov 2026.
The same steps, with screenshots-friendly formatting, are in the shared guide
"Pulita Website: Handover & Hosting Guide". Staff instructions for editing
content are in "How to Update the Pulita Website".

WHAT THE SITE IS
- Plain HTML, CSS and JavaScript. No build step, no database, no server code.
- Repository: pulita_new_energy (GitHub). The website lives in the folder
  "pulita-website". The CMS settings file ".pages.yml" sits at the TOP of the
  repository (not inside pulita-website).

STEP 1 - ACCEPT THE GITHUB REPOSITORY
1. Create a free company GitHub account (github.com) with a company email.
2. The developer transfers the repository to that account
   (Settings > General > Danger Zone > Transfer ownership).
3. Accept the emailed invitation within 24 hours.
4. Turn on two-factor sign-in. This account controls the website and the CMS.

STEP 2 - HOST THE WEBSITE (choose one)
Vercel:
1. Sign up at vercel.com with the company GitHub account.
2. Add New > Project > import pulita_new_energy.
3. Root Directory: pulita-website. Framework Preset: Other.
   Leave build command and output directory empty. Deploy.
   Note: Vercel's free Hobby plan is non-commercial; use Pro for a company site.
Netlify:
1. Sign up at netlify.com with the company GitHub account.
2. Add new site > Import an existing project > GitHub > pulita_new_energy.
3. Base directory: pulita-website. Build command: empty.
   Publish directory: pulita-website. Deploy.
Both hosts republish automatically about a minute after every change saved
to GitHub, including every CMS save.

STEP 3 - CONNECT pulitaenergy.com
1. In the host, add pulitaenergy.com and www.pulitaenergy.com.
2. Create the DNS records the host shows, at the domain registrar. Usually:
      A      @     76.76.21.21 (Vercel)   or 75.2.60.5 (Netlify)
      CNAME  www   cname.vercel-dns.com   or <your-site>.netlify.app
   Remove old A/CNAME records for the same names. Leave MX/TXT (email) alone.
3. Wait for verification. The https certificate is issued automatically.

STEP 4 - PAGES CMS
1. app.pagescms.org > Sign in with GitHub (company account).
2. Install the Pages CMS GitHub app on pulita_new_energy when asked.
3. Open the repository (branch main). Six sections should show:
   News & Exhibitions, Projects, Social media links, Gas supply partners,
   Contact details, Home page banner.
4. Collaborators (Admin area): invite staff by email. They need no GitHub
   account and cannot change settings or invite others.

FILES
  .pages.yml                         CMS settings (top of repo) - IT only
  pulita-website/*.html              9 pages
  pulita-website/assets/css/         styles.css, tailwind.css
  pulita-website/assets/js/          main.js, content-fallback.js
  pulita-website/assets/images/      all site photos (project photos included)
  pulita-website/assets/images/uploads/   photos uploaded through the CMS
  pulita-website/assets/docs/        datasheets (PDF), spec sheets (PDF/Excel),
                                     SONCAP certificate
  pulita-website/assets/docs/uploads/ datasheet PDFs uploaded through the CMS
  pulita-website/content/            CMS content (JSON) - edited through the CMS:
                                     news, projects, banner, contact, settings,
                                     partners, spare-parts, datasheets

RULES
- Never upload over pulita-website/content/ - it holds staff edits.
- Never re-upload the backup ZIP over the repository.
- Keep .pages.yml at the top of the repository with paths starting
  "pulita-website/". A copy inside pulita-website is ignored.
- On github.com, open the target folder first, then Add file > Upload files,
  and drag the files themselves (not their parent folder).
- Every change, including CMS saves, is a commit: undo from the history.
